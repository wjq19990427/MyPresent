# Task-56：待办树形层级 UI 修复

## 变更说明

**类型**：Bug 修复 + UI 优化  
待办树形结构的层级缩进在视觉上完全失效，所有层级节点看起来一样，无法区分父子关系。需重新实现缩进方案，使层级结构清晰可辨。

---

## 问题根因

**`components/tab_planning.py` · `_render_todo_row()`**

现有缩进实现：在列 `rc1` 中插入一个 `height:1px; width:{depth * 1.1}rem` 的不可见 div。由于这只是一列中的无高度占位，不影响其他列的水平位置，子节点与根节点在屏幕上处于完全相同的横坐标，层级信息丢失。

---

## 修复要求

**`components/tab_planning.py` · `_render_todo_node()` / `_render_todo_row()`**

用能真正产生视觉缩进的方案替换现有占位逻辑，使不同深度的节点在横向上有明显偏移。具体实现方式由 Codex 决定，但须满足：

1. **层级可辨**：depth=1 的子节点相比 depth=0 的根节点有可见的左侧偏移，depth=2 再进一步偏移，以此类推
2. **左侧树线**（推荐）：子节点左边有竖线或 L 形连接线，视觉上呈现文件树风格，类似飞书任务列表的子任务缩进
3. **不破坏现有列布局**：checkbox、展开/折叠按钮、操作按钮等功能元素保持可用
4. **已移入/已完成节点**同样应用相同的缩进规则

**可选实现思路（任选其一，不强制）：**
- 在 `_render_todo_node()` 外层用 `st.markdown` 注入带 `margin-left` 的 wrapper div，再渲染 container
- 用 CSS `border-left` 配合 `padding-left` 在容器外层产生竖线 + 缩进效果
- 用 Streamlit columns 的比例分配实现视觉偏移（需确保不同深度列宽比例正确）

---

## 验收（用户可见）

- [ ] depth=0 根节点与 depth=1 子节点在横向上有明显偏移
- [ ] depth=2 及更深层节点逐层继续偏移
- [ ] 子节点左侧有连接线或竖线等层级指示元素
- [ ] 展开/折叠、勾选、编辑、删除等按钮功能正常
- [ ] 已完成（删除线变灰）和已移入（置灰禁用）节点层级缩进同样正确
