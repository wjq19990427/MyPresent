# Task-53：待办树形结构重构

## 变更说明

**类型**：新功能  
待办列表升级为无限递归的树形结构（参考飞书风格）：每个待办可添加子级，子级可再添加子级；勾选父节点会级联标记全部后代为完成，并询问是否移入已完成事务；已移入完成的分支在原树中保留但永久置灰、禁止交互。

---

## 数据层

**`core/db_manager.py` + 新 patch 文件**

新增/改造支持树形节点的数据结构。每个待办节点需能表达：
- 所属父节点（或为根节点）
- 子节点集合（可为空）
- 完成状态：未完成 / 已完成 / 已移入已完成事务（三态）

Schema 设计（父子关系表达方式、字段名）由 Codex 决定，但须满足上述三态与递归查询需求，并提供对应数据库迁移 patch（参考 `patches/` 下已有 patch 格式）。

公开 CRUD 接口须覆盖：
- 在指定节点下新增子节点
- 递归读取某节点的完整子树
- 批量更新节点及其所有后代的完成状态
- 将某节点子树标记为"已移入完成事务"

## UI 层

**`components/tab_planning.py`**

### 添加子级

每个待办项旁有"添加子级"按钮（含递归，子级同样有此按钮）。

### 勾选行为

勾选某节点时：
1. 该节点及其**所有后代**立即显示删除线 + 颜色变暗。  
   **样式须直接复用 `tab_planning.py` 现有已完成条目的删除线 / 变色逻辑，不另起一套。**
2. 弹出确认："是否将此项及其子任务移入已完成事务？"
3. 用户确认后：记录已完成事务（复用 task-52 修好的含终止时间的完成弹窗流程），同时将该子树节点全部标记为"已移入"。

### 父节点完成判定

满足以下**任一**条件，父节点判定为完成：
- 直接勾选父节点本身
- 父节点的所有直接/间接子节点均已完成

部分子节点完成时，父节点显示**完成百分比**（已完成叶子数 / 总叶子数）或半勾（indeterminate）效果。

### 已移入完成的节点

- 视觉上**保留在树中**，呈变色/置灰状态（参考现有已完成条目样式）。
- **不响应任何交互**：勾选框禁用、"添加子级"按钮隐藏。
- 后续新勾选操作到达此节点时，跳过（不触发弹窗，不重复移入）。

## 已知约束 / 陷阱

- `migrate_overdue_todos()` 的迁移逻辑须适配树形结构：迁移根节点时，其子树整体跟随迁移，不拆散父子关系。
- 已移入完成事务的节点，`migrate_overdue_todos()` 不得再次迁移或重置其状态。
- 完成弹窗流程依赖 task-52 的终止时间修改；**本卡须在 task-52 合并后开始**。

## 验收（用户可见）

- [ ] 每个待办项（包括子级）均有"添加子级"按钮，可无限嵌套
- [ ] 勾选某节点后，该节点及所有子级文字出现删除线并变暗
- [ ] 弹出确认框，询问是否移入已完成事务
- [ ] 确认后，进入含终止时间的完成记录弹窗（task-52 流程）
- [ ] 完成记录后，已完成分支在树中变为置灰、不可点击
- [ ] 父节点所有子级均完成 → 父节点自动显示完成状态
- [ ] 父节点部分子级完成 → 父节点显示完成百分比或半勾效果
- [ ] 直接勾选父节点 → 父节点及所有后代同步标记完成
- [ ] 日历翻月后，已移入完成的节点仍保持置灰、不可勾选
